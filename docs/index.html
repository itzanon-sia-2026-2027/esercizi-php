🚀 Esercizi PHP con PDO

Tutorial: setup, VSCode, SQLite/MySQL, XAMPP e Altervista

🎯 Da dove iniziare

Gli esercizi nella cartella lavoro/ usano MySQL, come nelle lezioni. La soluzione completa in biblioteca/ include invece configurazioni separate per MySQL e SQLite.

  • MySQL: server MySQL/MariaDB di XAMPP o Altervista; è il database usato per svolgere le lezioni.
  • SQLite: disponibile nella soluzione biblioteca/; usa un file e non richiede un server database.

Percorso più veloce: importa il profilo VSCode (tab 🧰), apri la cartella del progetto, apri un file index.php e lancia il task "4. Avvia Server PHP (file corrente)".

Scegliere il database

Per le lezioni usa MySQL e configura le credenziali in lavoro/connessione.php. Nella soluzione completa i driver sono separati: biblioteca/connessione.mysql.php e biblioteca/connessione.sqlite.php; il selettore è biblioteca/connessione.php.

Soluzione biblioteca: SQLite

  • La soluzione biblioteca/ seleziona SQLite inizialmente. La connessione è configurata in biblioteca/connessione.sqlite.php.
  • Il database è il file database/biblioteca.sqlite, creato automaticamente al primo accesso, con tabelle e dati di esempio (database/schema_sqlite.sql).
  • Per ripartire da zero cancella il file biblioteca.sqlite.
  • Il file è escluso da Git e protetto da database/.htaccess (non scaricabile da browser su Apache/Altervista).
  • Per ispezionarlo: estensione VSCode "SQLTools SQLite" oppure DB Browser for SQLite.
  • Richiede l'estensione PHP pdo_sqlite (inclusa in XAMPP e su Altervista).

MySQL per le lezioni e la soluzione

  1. Per le lezioni, modifica in lavoro/connessione.php le variabili $host, $db, $user e $pass. In XAMPP i valori predefiniti sono localhost, biblioteca, root e password vuota.
  2. Per la soluzione completa, modifica le credenziali in biblioteca/connessione.mysql.php e seleziona quel file in biblioteca/connessione.php.
  3. Avvia MySQL e importa database/schema.sql con phpMyAdmin o il task 9. Lo schema crea il database biblioteca.
💡 Perché SQLite nella soluzione? Altervista offre un solo database MySQL per account: SQLite permette alla soluzione completa di avere un file database dedicato.

Scrivere SQL portabile

Le query degli esercizi usano SQL portabile e segnaposto PDO posizionali (?) per i parametri. Evita funzioni specifiche (es. NOW() di MySQL).

Usare il database nei tuoi file

<?php
require_once 'connessione.php';

try {
    $stmt = $pdo->prepare("SELECT * FROM libri WHERE id = ?");
    $stmt->execute([$_GET['id']]);
    $libro = $stmt->fetch();
} catch (PDOException $e) {
    die('Errore database: ' . htmlspecialchars($e->getMessage()));
}
?>

Per un progetto libero con SQLite (es. il file creato dal task 2):

$pdo = new PDO('sqlite:database.db', null, null, [
    PDO::ATTR_ERRMODE            => PDO::ERRMODE_EXCEPTION,
    PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC
]);

Setup con XAMPP su Windows

Credenziali predefinite MySQL di XAMPP: utente root, password vuota.

Passo 1: Installa XAMPP e VSCode

Scarica XAMPP da apachefriends.org e installalo in C:\xampp (Apache, MySQL, PHP, phpMyAdmin). In laboratorio è già installato.

Passo 2: Scarica il progetto

git clone https://github.com/itzanon-sia-2026-2027/esercizi-php.git

Oppure scarica lo ZIP da GitHub e scompattalo. Apri la cartella con VSCode (profilo 5sia_lab112).

Passo 3A: Server integrato PHP (consigliato)

  1. Apri un file del progetto (es. lavoro/categorie.php).
  2. Esegui il task "4. Avvia Server PHP (file corrente)" (pulsante ▶️ Avvia Server PHP nel pannello Favorites).
  3. Si apre http://localhost:3000/lavoro/categorie.php.

Con SQLite non serve altro. Con MySQL avvia anche MySQL dal XAMPP Control Panel e importa lo schema (tab 🗄️).

Passo 3B: Apache di XAMPP

  1. Copia il progetto in C:\xampp\htdocs\esercizi-php\.
  2. Avvia Apache (e MySQL se usi MySQL) dal Control Panel.
  3. Apri http://localhost/esercizi-php/.

Workflow giornaliero

  1. Apri la cartella del progetto in VSCode
  2. Avvia il server (task 4) e, se serve, MySQL
  3. Modifica i file, salva e ricarica il browser
  4. Salva il lavoro con Git (git add ., git commit)

Pubblicare su Altervista

Passo 1: Crea l'account

Registrati su it.altervista.org: il tuo sito sarà https://NOMEACCOUNT.altervista.org.

Passo 2: Configura il caricamento FTP con il profilo

  1. Esegui il task "1. Inizializza Progetto & SFTP Altervista" e inserisci la tua cartella remota (es. cognome_nome).
  2. Apri .vscode/sftp.json e sostituisci NOMEACCOUNT (host e username) e PASSWORD con i dati Altervista.
  3. La cartella .vscode non va su Git (contiene la password): è già in .gitignore.
  4. Con uploadOnSave ogni file salvato viene caricato; per caricare tutto: Ctrl+Shift+P → SFTP: Upload Project (se non riesci, prova SFTP: Upload Folder).
{
  "name": "Altervista",
  "host": "ftp.NOMEACCOUNT.altervista.org",
  "protocol": "ftp",
  "port": 21,
  "username": "NOMEACCOUNT",
  "password": "PASSWORD",
  "remotePath": "/cognome_nome/",
  "uploadOnSave": true
}

Alternativa: pubblicazione manuale con GitHub Actions

  1. Nel repository GitHub apri Settings → Secrets and variables → Actions e crea i secret del repository FTP_USERNAME (nome account Altervista) e FTP_PASSWORD (password FTP). Non inserirli nei file del repository.
  2. Apri Actions → Deploy su Altervista (Manuale) → Run workflow, scegli il branch da pubblicare e avvia la workflow. Controlla il risultato nella pagina dell'esecuzione.
  3. Il progetto viene pubblicato in /5bs/esercizi-php/, raggiungibile da https://NOMEACCOUNT.altervista.org/5bs/esercizi-php/.

La sincronizzazione esclude i database SQLite, ma può sovrascrivere i file pubblicati e cancellare dal server quelli rimossi dal repository dopo una pubblicazione precedente. I file di connessione MySQL fanno parte del repository: non inserire password reali nei file e fai un backup prima di pubblicare.

La workflow usa FTP sulla porta 21: credenziali e file viaggiano senza cifratura. Verifica nelle impostazioni Altervista che l'accesso FTP sia abilitato e che il server accetti la connessione dai runner GitHub.

Passo 3A: Database SQLite (consigliato)

  1. La soluzione biblioteca/connessione.php seleziona SQLite su Altervista; non occorre impostare un driver.
  2. Carica il progetto e apri https://NOMEACCOUNT.altervista.org/cognome_nome/lavoro/.
  3. Il file database/biblioteca.sqlite viene creato sul server al primo accesso. Il database online è separato da quello locale.
La cartella database/ deve essere scrivibile dal server. Se compare "unable to open database file" imposta i permessi della cartella dal File Manager di Altervista.

Passo 3B: Database MySQL

  1. Dal pannello Altervista apri phpMyAdmin (database my_NOMEACCOUNT) e importa database/schema.sql dopo aver rimosso le istruzioni CREATE DATABASE e USE.
  2. Per gli esercizi inserisci le credenziali Altervista in lavoro/connessione.php. Per la soluzione, inseriscile in biblioteca/connessione.mysql.php e modifica biblioteca/connessione.php perché includa la connessione MySQL anche su Altervista.

Altervista dà un solo database: se lo condividi tra più progetti, usa un prefisso per le tabelle oppure passa a SQLite.

Problemi Comuni e Soluzioni

❌ could not find driver

L'estensione PDO del database scelto non è attiva. In XAMPP apri C:\xampp\php\php.ini e togli il ; da extension=pdo_sqlite / extension=pdo_mysql, poi riavvia il server.

❌ unable to open database file (SQLite)

La cartella database/ non è scrivibile o il percorso è errato. Controlla i permessi (su Altervista dal File Manager).

❌ Access denied for user / Unknown database (MySQL)

Controlla host, database, utente e password in lavoro/connessione.php oppure in biblioteca/connessione.mysql.php, e verifica di aver importato database/schema.sql. XAMPP: root senza password.

❌ Connection refused (MySQL)

MySQL non è avviato: avvialo dal XAMPP Control Panel oppure passa a SQLite.

❌ Il task "Avvia Server PHP" non parte / porta occupata

Chiudi il terminale del server precedente (cestino del terminale) e rilancia il task. Verifica che PHP sia in C:\xampp\php\php.exe.

❌ Pagina bianca / Errore 500

Attiva gli errori all'inizio del file: ini_set('display_errors', 1); error_reporting(E_ALL); e leggi il messaggio.

❌ Caratteri strani (à, è, ì, ò, ù)

Salva i file in UTF-8 e usa <meta charset="UTF-8">. Con MySQL il charset utf8mb4 è già impostato nel DSN.

❌ Upload FTP fallito (Altervista)

Verifica host, username e password in .vscode/sftp.json e che il protocollo sia ftp sulla porta 21.
